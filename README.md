# Unified Job Application Tracker with Evidence Based Matching

A candidate-side job application management and resume diagnostic system that combines application tracking, ATS-style resume parsing, AI-assisted analysis, and deterministic evidence-based resume-to-job-description matching.

---

## Overview

The **Unified Job Application Tracker with Evidence Based Matching** is designed to help candidates manage their job applications while also understanding how well their resume represents the requirements of a specific job description.

Traditional job application tracking tools mainly focus on storing information such as company names, job titles, application dates, and application status. Resume analysis is usually handled separately. This project combines both workflows into a single application.

The system allows users to:

- Manage and track job applications
- Maintain application history and interview information
- Upload and manage resumes
- Process resumes through an ATS-style parser
- Analyze job descriptions and identify requirements
- Compare resume evidence against individual job requirements
- Classify requirements as `MATCHED`, `PARTIALLY MATCHED`, or `MISSING`
- Identify evidence gaps
- Generate safe resume improvement suggestions
- Calculate a deterministic resume-to-requirement match score

The system is designed around a separation of responsibilities between **ATS parsing, AI-assisted semantic interpretation, and deterministic requirement matching**.

## Key Features

### Application Management

- User authentication and login
- Create, update, and manage job applications
- Track application status
- Store company, role, location, dates, and notes
- Maintain application history
- Store interview information
- Dashboard and application analytics

### Resume Management

- Upload resumes
- Maintain resume history
- Process uploaded resumes through OpenCATS
- Use parsed resume information for subsequent analysis

### ATS-Style Resume Parsing

- Integration with **OpenCATS**
- OpenCATS is hosted locally using **Docker**
- Resume documents are submitted to the local OpenCATS instance
- Extracted resume information is returned to the application for further processing

### AI-Assisted Resume and Job Analysis

- Job description requirement extraction
- Semantic interpretation of resume and job description content
- Resume evidence analysis
- Evidence gap generation
- Safe improvement suggestions
- Keyword optimization suggestions

### Evidence-Based Matching

Each identified job requirement is independently classified as:

- `MATCHED`
- `PARTIALLY MATCHED`
- `MISSING`

The system provides more information than an overall percentage by showing the requirements and evidence behind the result.

### Deterministic Scoring

The final match percentage is calculated by application code rather than being directly generated by the language model.

The scoring engine uses requirement importance:

- **REQUIRED** requirements have a weight of `1.0`
- **PREFERRED** requirements have a weight of `0.5`
- `MATCHED` receives the full requirement weight
- `PARTIALLY MATCHED` receives half of the requirement weight
- `MISSING` receives zero

The final score is calculated from the earned weighted score relative to the total possible weighted score.

## What Makes the System Different?

The main focus of this project is **explainable resume-to-job-description matching**.

Instead of treating the final percentage as the complete result, the system breaks the comparison down into individual requirements and provides context for the score.

> **Not just the score — the system shows the evidence behind the score.**

The architecture separates the responsibilities of different components:

| Component | Responsibility |
|---|---|
| OpenCATS | ATS-style resume parsing |
| AI / LLM | Semantic interpretation of resume and job description |
| Requirement Matcher | Requirement-level comparison |
| Deterministic Scoring Engine | Authoritative match score calculation |
| Streamlit Application | User interface and workflow |
| SQLite | Application and user data storage |

The language model does **not** directly determine the final match percentage.

Instead, AI is used where semantic interpretation is useful, while the final requirement classification and score are handled by deterministic application logic.

This separation makes the scoring process more consistent, testable, and explainable.

## How Resume-JD Matching Works

The matching workflow follows these stages:

### 1. Resume Upload

The user uploads a resume through the application.

### 2. ATS Parsing

The resume is submitted to the locally hosted OpenCATS service running inside Docker.

OpenCATS extracts available resume information and returns the parsed representation to the application.

### 3. Resume Processing

The parsed resume information becomes the input for the subsequent analysis pipeline.

### 4. Job Description Analysis

The supplied job description is analyzed to identify and structure individual requirements.

Requirements are represented with information such as:

- Requirement description
- Category
- Importance

### 5. Resume Evidence Analysis

The system evaluates whether the resume contains evidence relevant to each requirement.

Evidence can come from areas such as:

- Education
- Work experience
- Projects
- Technical skills
- Certifications
- Technical descriptions
- Quantified achievements

### 6. Requirement Classification

Each requirement receives exactly one classification:

```text
MATCHED
PARTIALLY MATCHED
MISSING
```

**MATCHED** indicates that sufficient relevant evidence is present.

**PARTIALLY MATCHED** indicates that related evidence exists but does not completely satisfy the requirement.

**MISSING** indicates that sufficient supporting evidence could not be identified.

### 7. Evidence Gaps

For requirements that are partially matched or missing, the system can provide evidence gaps explaining what is not sufficiently represented.

### 8. Improvement Suggestions

The analysis can provide suggestions for improving the representation of existing qualifications.

The system is designed to avoid fabricating qualifications or unsupported experience.

### 9. Deterministic Score Calculation

The deterministic scoring engine calculates the final match percentage from the requirement classifications and requirement importance.

The language model does not directly generate the final percentage.

## Installation and Setup

### Prerequisites

The application requires:

- Python
- Docker Desktop
- Git
- A configured AI model/provider
- OpenCATS running locally through Docker

### Python Environment

Create and activate a Python virtual environment:

```bash
python -m venv .venv
```

Windows:

```bash
.venv\Scripts\activate
```

Install the Python dependencies used by the project.

If a dependency file is provided with the repository, install from that file:

```bash
pip install -r requirements.txt
```

### SQLite

SQLite is used as the application's local database and does not require a separate database server.

The application manages its database through the database layer.

### OpenCATS

OpenCATS is **not hosted as an external web service in this project**.

It is hosted **locally using Docker**.

The local environment consists of the OpenCATS application and its supporting database services.

Typical local services used by the current setup include:

```text
OpenCATS
MySQL
phpMyAdmin
```

The exact Docker configuration should be taken from the project's local Docker environment rather than assumed from the README.

### AI Model Configuration

The AI analysis layer is designed to communicate with an AI model through the configured provider.

Depending on the configuration, the model can be:

- A **cloud-hosted model**, or
- A **personally downloaded/local model**

The application itself does not train its own foundation model.

The AI model is used for semantic interpretation, requirement extraction, evidence analysis, and generation of analysis/suggestion content.

API credentials or private configuration values should **not** be committed to the repository.

## Limitations

The current implementation has several limitations.

### Resume Parsing Dependency

The quality of downstream analysis depends partly on the information successfully extracted by OpenCATS.

### AI Interpretation

AI-assisted analysis can depend on the selected model and its ability to correctly interpret unstructured resume and job-description content.

### Model Availability

Cloud-based models can be subject to provider availability, usage limits, or account-specific restrictions. Local models depend on the available hardware and model configuration.

### Development-Oriented Deployment

The current architecture is primarily designed for local/development use, including locally hosted OpenCATS and SQLite.

### Complex Experience Reasoning

Highly complex temporal or contextual relationships in professional experience may require further development for more advanced date-aware and evidence-aware analysis.

### No Hiring Prediction

The system does not attempt to predict whether a candidate will receive an interview or job offer.

## Privacy and Security

The application stores job application and resume-related information as part of its local workflow.

OpenCATS is hosted locally through Docker in the current setup.

AI processing depends on the configured model:

- When using a **local/downloaded model**, analysis can be performed through the local model environment.
- When using a **cloud-based model**, relevant resume and job-description content may be sent to the configured cloud AI provider for processing.

Users should therefore review the privacy and data-handling policies of the selected AI provider before processing sensitive resume information through a cloud model.

API keys, credentials, passwords, and other private configuration values should never be committed to the repository.
